# Дочистка кода по ревью качества

## Why

Перед внешним ревью кода нужно закрыть оставшиеся замечания внутреннего ревью 14.11.2026:
дубли, нарушения слоёв, N+1, мёртвый код, слабая типизация, слишком длинные модули, расхождение
моделей с миграциями. Ошибки, приватность и надёжность из того же ревью уже исправлены
(коммит «fix: harden uploads, sessions and background processing»).

## What Changes

- Бэкенд: общие хелперы вместо дублей (условие «публичный маршрут», подсчёт бегунов, вердикт
  сравнения, порог равенства, Author/ачивки); SQL коридора и чтение корня маршрута — в infra;
  N+1 в отметках км, в лучшем совпадении и в пересчёте рейтингов; разбиение `api/tracks.py` и
  `match()`; типизированные структуры вместо `dict[str, Any]` и строковых статусов; удаление
  мёртвого кода и устаревших комментариев; модели приведены к миграциям, тест на совпадение;
  общие тестовые хелперы вместо импорта между тестовыми модулями.
- Фронтенд: общие хелперы ошибок и текста вердикта, хук `useMyTracks`; обработка ошибок
  мутаций; `queryClient.clear()` при выходе; один refresh на все вкладки; «Ещё» не превышает
  лимит API; карта не пересоздаётся на каждом рендере; строки TrackMap — в i18n; типизация
  категорий; разбиение `HomePage`; удаление мёртвого кода.
- Поведение и API не меняются: `openapi.json` остаётся прежним.

## Impact

Код бэкенда (`app/api`, `app/infra`, `app/domain`, `tests`) и фронтенда (`src`). Миграция
схемы не требуется, кроме случаев, когда модель расходится с уже применённой миграцией — тогда
правится модель.
