# Design

## Context
Есть группы (`attempts`, `parent_track_id`) и учёт скачиваний (`track_downloads`). Поиск
сортирует «Популярные» по живой формуле (add-map-search). Настройки: `popularity.weights`,
`popularity.recalc_interval_s` = 3600.

## Decisions
- **`popularity_scores`** (track_id, category, period, runners, downloads, likes, value,
  computed_at), ключ (track_id, period). Пишется только для опубликованных публичных
  исходных треков, не удалённых и не скрытых; устаревшие строки удаляются при пересчёте.
- **Бегуны** — уникальные авторы активных попыток группы плюс автор маршрута.
- **Пересчёт** — чистая функция формулы (`app/domain/ratings`) и один SQL-проход по трекам;
  задача `recalc_popularity` в Celery beat с интервалом из настроек (читается при старте
  воркера); воркер запускается с `-B` (для прототипа одного процесса beat достаточно).
- **`GET /ratings?category=&limit=`** — места, трек, автор, бегуны, скачивания, значение,
  время пересчёта. Только период «всё время».
- **Поиск**: сортировка «Популярные» — по `popularity_scores.value`, при отсутствии строки
  (трек опубликован после последнего пересчёта) — 0, затем по дате публикации.
- **Фронт**: `/ratings` со вкладками категорий (состояние в адресе `?category=`), пункт
  «Рейтинги» в нижней навигации и шапке.

## Non-Goals
Периоды, города, рейтинг бегунов, лайки — этап 2.
