## ADDED Requirements
### Requirement: Automatic Matching
При публикации публичного трека система SHALL автоматически искать совпадающий исходный трек; приватные треки и треки «по ссылке» MUST NOT сопоставляться.

#### Scenario: Same route faster
- **WHEN** бегун публикует публичный трек по тому же маршруту, что и исходный, на 18 с быстрее
- **THEN** трек становится попыткой в группе исходного с отметкой «превзошёл»

#### Scenario: Link visibility
- **WHEN** бегун публикует такой же трек с видимостью «по ссылке»
- **THEN** сопоставление не выполняется

### Requirement: Route Match Rules
Попытка MUST засчитываться, только если старт и финиш в пределах 50 м, не менее 90% точек исходного трека в коридоре 30 м, направление совпадает, а длина отличается не более чем на 3%; все пороги берутся из настроек.

#### Scenario: Shortcut through park
- **WHEN** бегун срезал часть маршрута, и в коридоре 81% точек
- **THEN** совпадение не засчитывается

#### Scenario: Reverse direction
- **WHEN** бегун пробежал маршрут в обратном направлении
- **THEN** совпадение не засчитывается

### Requirement: Warm-up Trimming
Для линейного маршрута система SHALL вырезать из попытки участок между точками старта и финиша исходного трека и сравнивать только его.

#### Scenario: Warm-up before start
- **WHEN** трек 6,1 км включает разминку до старта маршрута 5,2 км
- **THEN** сравнивается время вырезанного участка 5,2 км

### Requirement: Loop Routes
Для кругового маршрута (старт и финиш исходного трека ближе 50 м) система SHALL NOT вырезать участок: общая дистанция попытки MUST отличаться не более чем на 3%.

#### Scenario: Two laps
- **WHEN** бегун пробежал круговой маршрут два раза подряд
- **THEN** совпадение не засчитывается

### Requirement: Privacy Zone Compensation
Если у автора исходного трека есть скрытые зоны, проверка SHALL идти по видимой части, а время попытки на скрытых участках MUST досчитываться по её среднему темпу на видимой части.

#### Scenario: Author hid start
- **WHEN** автор скрыл первые 300 м, а бегун пробежал видимую часть
- **THEN** попытка засчитывается, к её времени добавлено время 300 м по её среднему темпу

### Requirement: Root Track
Исходным треком SHALL считаться первый по дате публикации публичный трек маршрута; дата пробежки не учитывается.

#### Scenario: Older run uploaded later
- **WHEN** бегун загружает пробежку двухлетней давности по существующему маршруту
- **THEN** она становится попыткой, а не новым исходным треком

#### Scenario: Root hidden by moderator
- **WHEN** модератор скрывает исходный трек
- **THEN** исходным становится следующий трек группы по дате публикации

### Requirement: Result Comparison
Сравнение SHALL идти по общему времени участка; разница меньше 1 с считается равным результатом.

#### Scenario: Equal result
- **WHEN** попытка медленнее исходного на 0,6 с
- **THEN** она встаёт в группу без отметки «превзошёл»

### Requirement: Group Table
Таблица группы SHALL показывать лучшую попытку каждого бегуна; попытки автора на свой трек идут в таблицу без отметки «превзошёл».

#### Scenario: Two attempts by one runner
- **WHEN** у бегуна две попытки в группе
- **THEN** в таблице показана только лучшая из них

### Requirement: Detach Attempt
Бегун SHALL иметь возможность отвязать свою попытку от группы; отвязанный трек MUST NOT становиться исходным для этого маршрута.

#### Scenario: Detach at preview
- **WHEN** бегун нажимает «Не засчитывать» в превью
- **THEN** трек публикуется как обычный и не попадает ни в одну группу

### Requirement: Match Check
Система SHALL по запросу бегуна проверять его трек против выбранного исходного и называть невыполненные правила и место схода с коридора.

#### Scenario: Explain failure
- **WHEN** бегун запускает «Проверить мою пробежку» для трека со срезкой
- **THEN** ответ содержит правило покрытия, фактическое значение 81% и координату схода
