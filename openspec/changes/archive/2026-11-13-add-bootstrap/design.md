## Context
Трёхзвенная архитектура из раздела 9 ТЗ, стек зафиксирован в `docs/project.md`.

## Decisions
- Монорепозиторий: агенту проще держать фронт, бэк и спеки в одном контексте.
- Таблица `settings` (key, value jsonb) с первого дня: пороги сопоставления,
  границы категорий и коэффициенты популярности меняются без деплоя.
  Сервис настроек читает значение из БД при каждом обращении (без кеша в процессе);
  если понадобится кеш — только с коротким TTL. Админ-API для изменения — в этапе 2,
  пока значения меняются SQL-запросом.
- Celery-воркер — отдельный контейнер с тем же образом, что api.
- `GET /health` проверяет БД (`SELECT 1`), Redis (`PING`) и S3 (наличие бакета);
  любая ошибка → 503.
- Python-зависимости — `uv` (pyproject.toml + uv.lock); фронт — npm.
- API-клиент: FastAPI экспортирует `backend/openapi.json` скриптом, фронт генерирует
  типы через `openapi-typescript` и использует `openapi-fetch`. CI перегенерирует оба
  артефакта и падает на `git diff`.
- Тесты с PostGIS используют testcontainers (`postgis/postgis:16-3.5`, только amd64 — на Apple Silicon через эмуляцию) и локально, и в CI —
  отдельный сервис в GitHub Actions не нужен.
- Локальное S3 — SeaweedFS (`chrislusf/seaweedfs`): публичные образы MinIO больше не выпускаются.
  Бакет создаётся идемпотентно скриптом `app.scripts.init_storage` при старте api.
- Форматирование и линт: ruff + black, mypy strict для `app/domain`; eslint + prettier, tsc strict.
- Внешнего репозитория пока нет: CI-workflow пишется и проверяется локально;
  прогон на настоящем PR — после подключения GitHub.

## Risks
- testcontainers требует Docker на раннере — на `ubuntu-latest` он есть.
