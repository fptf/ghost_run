# Design

## Context
Есть пользователи с точкой дома и радиусом (add-auth-profile), S3, Celery, таблица `settings`.
Карты на фронте ещё нет; провайдер тайлов выбирается здесь, а не в add-map-search, потому что
превью требует карту. Реальные GPX пользователя содержат координаты у дома и в git не хранятся.

## Goals / Non-Goals

**Goals:**
- Надёжный разбор GPX/TCX/FIT в одну модель и одинаковые показатели для всех форматов.
- Данные, пригодные для сопоставления (add-route-matching): геометрия со временем, границы видимой части.
- Приватность: чужим никогда не уходят точки из скрытой зоны, фото — без EXIF.

**Non-Goals:**
- Сопоставление, плашка совпадения, «Не засчитывать» — add-route-matching (в превью только место).
- Карта всех треков, поиск, карточка трека для других — add-map-search.
- Удаление исходного трека с попытками (ФТ-9, «только скрытие») — add-route-matching.

## Decisions
- **Конвейер**: `POST /tracks` (multipart) проверяет размер (по потоку, не по заголовку), формат
  (расширение + сигнатура: `<gpx`, `<TrainingCenterDatabase`, заголовок `.FIT`), SHA-256 и лимит
  загрузок → файл в S3 `users/{uid}/tracks/{tid}/source.{ext}` → Track `processing` → задача
  `process_track`. Воркер → `draft` (готов, виден только автору) или `rejected` с причиной.
  Фронт опрашивает `GET /tracks/{id}` раз в секунду. Публикация — `PATCH` с видимостью.
- **Доменная модель** (`app/domain/tracks`, mypy strict, без I/O): `Point(lat, lon, t, ele)`;
  парсеры gpxpy / lxml (TCX) / fitparse → `list[Point]`; метрики считаются в локальной UTM-зоне
  (pyproj) по очищенным точкам.
- **Очистка и метрики**: точка-выброс — если до неё нужна скорость > `metrics.max_point_speed_mps`
  (12 м/с); остановка — отрезок со скоростью < `metrics.stopped_speed_mps` (0,5 м/с), он входит в
  общее время и не входит во время движения. Набор высоты — сумма подъёмов после сглаживания
  скользящим окном и порога `metrics.elevation_noise_m` (3 м). Темп = общее время / дистанция
  (как в 5.2). Новые пороги — новыми ключами `settings`.
- **Хранение без таблицы TrackPoint.** Отклонение от раздела 6 ТЗ: 1 млн треков × ~3000 точек =
  миллиарды строк. Вместо этого `geometry LINESTRINGZM, 4326` (Z — высота, M — секунды от старта):
  PostGIS умеет искать по ней, а M даёт время в любой точке для сопоставления и досчёта скрытых
  зон. Плюс `visible_geometry LINESTRINGM` и `visible_from_m` / `visible_to_m` (границы видимой
  части по дистанции), `start_point` / `finish_point` видимой части, GIST-индексы. Сплиты — таблица
  `track_splits`. Исходный файл остаётся в S3.
- **Рабочие геометрии (решение 13.11.2026).** Полная `geometry` — только для метрик и времени.
  Из видимой части строятся производные с эталонной сложностью: `route_geometry` — пересэмплинг
  с равным шагом `geometry.resample_step_m` (10 м) для сопоставления (доля точек в коридоре 5.1
  корректна только при равномерной плотности); `display_geometry` — Дуглас—Пекер с допуском
  `geometry.simplify_tolerance_m` (5 м) для карты и API. Обе считаются в UTM, чистыми функциями.
- **Скрытая зона** — по ФТ-4 (подтверждено 13.11.2026): скрываются начало (до первого выхода из круга) и конец (после
  последнего входа в круг). Проходы через зону в середине трека остаются видимыми. Пересчёт
  всех треков бегуна — задача воркера при изменении дома или радиуса.
- **Видимость и статусы**: `status` = processing | rejected | draft | published;
  `visibility` = public | link | private. Чужим: published + public/link по id (uuid
  неугадываем), списки — только public. Чужим отдаётся только `visible_geometry`.
- **Фото**: JPEG/PNG/WebP до 10 МБ, Pillow перекодирует с удалением EXIF и уменьшает до 2048 px.
- **Удаление**: треки удаляются каскадом в БД; префикс S3 `users/{uid}/` уже чистится
  реестром из add-auth-profile — добавляем тест, что туда попадают и треки, и фото.
- **Карта** (решение 13.11.2026): MapLibre GL JS + растровые тайлы OpenStreetMap
  (`tile.openstreetmap.org`), стиль встроен в код (`src/lib/mapStyle.ts`) — без загрузки стиля,
  шрифтов и спрайтов, поэтому трек рисуется сразу (~0,1–0,2 с), подложка догружается под ним.
  OpenFreeMap отклонён: его адреса Cloudflare 8.x у российских провайдеров обрывают ответы
  после ~20 КБ, карта появлялась через минуту и больше. Свои тайлы не делаем.
  Правила OSM: атрибуция обязательна, для большой нагрузки нужен другой провайдер — меняется
  только `mapStyle.ts`. Воркер MapLibre подключается через Vite `?worker&url`.
- **График темпа** — свой небольшой SVG-компонент, без библиотеки графиков: нужен один график.
- **Фикстуры**: `tools/anonymize_gpx.py` сдвигает долготу на фиксированную величину (расстояния не
  меняются), срезает по 500 м с начала и конца, убирает метаданные устройства. В
  `backend/tests/fixtures/tracks/` попадают только обезличенные копии. TCX и FIT генерируются из
  них же (`tools/convert_track.py`, FIT — через `fit-tool`, dev-зависимость) для теста «три
  формата». Синтетика (остановка, выброс, без времени, транспорт, 10,3 км) строится в тестах кодом.

## Risks / Trade-offs
- [Нет таблицы точек — подтверждено 13.11.2026] → точки читаются из геометрии (`ST_DumpPoints`) или из файла в S3; для
  сопоставления этого достаточно, для аналитики по точкам — нет (не нужна по ТЗ).
- [Внешние тайлы OSM: лимиты политики использования] → при росте нагрузки перейти на коммерческий
  провайдер растровых тайлов; трек и показатели видны и без подложки.
- [Конвертированные TCX/FIT не равны выгрузке с часов] → проверяют наши парсеры на корректных
  файлах; реальные выгрузки добавим в фикстуры, когда появятся.
- [PostGIS под эмуляцией на Apple Silicon] → тест «до 10 секунд» меряет только доменный разбор и
  расчёт, а не запись в эмулированную БД.
