# Design

## Context
Есть треки с видимой упрощённой геометрией (`display_geometry`), стартом видимой части и
GIST-индексами (add-track-upload). Карта — MapLibre + растровые тайлы OSM со встроенным стилем.
Попыток ещё нет (add-route-matching), рейтингов — тоже (add-ratings).

## Goals / Non-Goals

**Goals:** главная карта с фильтрами, списком и поиском; карточка трека с GPX; навигация.

**Non-Goals:**
- Таблица группы, «Проверить мою пробежку» — add-route-matching (здесь место-заглушка).
- Популярность как в ФТ-28 с почасовым пересчётом — add-ratings; здесь сортировка по живой
  формуле из скачиваний (попыток пока нет).
- Нагрузочный тест на 1 млн треков — отложен (прототип, решение 13.11.2026).

## Decisions
- **`parent_track_id`** добавляется сейчас (модель данных ТЗ, раздел 6): карта и поиск берут
  только треки без родителя. Заполнять его будет add-route-matching.
- **Скачивания** — таблица `track_downloads` (track_id, user_id null, created_at): нужна для
  популярности по периодам (ФТ-29) в add-ratings.
- **`GET /tracks/search`**: bbox + zoom + фильтры + сортировка + пагинация списка.
  - zoom ≤ `map.cluster_max_zoom` (11) → кластеры: `ST_SnapToGrid(start_point, cell)` с размером
    ячейки по зуму, число треков и центр ячейки.
  - иначе → линии `display_geometry`, дополнительно упрощённые под зум, не больше
    `map.max_lines` (300) самых подходящих по сортировке.
  - пересечение с bbox — по `display_geometry && envelope` (GIST).
  - текст `q` — pg_trgm (`ILIKE` + GIN-индексы на название трека, имя и город автора);
    при `q` область карты не ограничивает выдачу.
- **GPX** — `GET /tracks/{id}/gpx` из `visible_geometry` без времени (маршрут для часов), доступ
  как у трека; каждое скачивание пишет строку в `track_downloads`.
- **Отметки км** — в ответе трека: для каждого целого км в пределах видимой части —
  `ST_LineInterpolatePoint(visible_geometry, доля)` с учётом `visible_from_m`.
- **Фронт**:
  - состояние карты и фильтров — в query-параметрах (`lat`, `lon`, `z`, `cat`, `dmin`, …);
    без них — Владивосток (43.1155, 131.8855), зум 12.
  - кластеры, отметки км, старт и финиш — HTML-маркеры MapLibre (у встроенного растрового
    стиля нет шрифтов для подписей на карте).
  - десктоп: левая панель (фильтры, список, карточка выбранного трека) + карта; телефон: карта
    на весь экран, фильтр дистанции сверху, выдвижной список снизу, карточка — отдельный экран.
  - навигация: телефон — нижняя панель «Карта / Профиль» («Рейтинги» появятся в add-ratings),
    десктоп — меню в шапке.
  - страницы с картой подгружаются лениво (`React.lazy`): шапка и навигация не ждут MapLibre.
- **«Новые»** — `published_at >= now() - search.new_days` (7 дней); тот же признак `is_new` в элементах
  выдачи для пометки «новый».
- **Исходная область** — Владивосток или, если бегун согласился на «треки рядом», его местоположение;
  хранится в localStorage вместе с ответом на вопрос (обёрнуто в try/catch — без хранилища вопрос
  просто задаётся снова). «Сбросить» очищает query-параметры и переводит карту в исходную область.
- **Список**: на телефоне — выдвижная панель с явной кнопкой «Скрыть список / Показать список (N)»,
  в свёрнутом виде только строка-заголовок; на десктопе левую панель можно скрыть, на карте
  остаётся кнопка «Список (N)».
- **Настройки профиля**: «Назад» и переход в профиль после сохранения — как у формы трека.

## Risks / Trade-offs
- [Живая сортировка по популярности без пересчёта] → на прототипе достаточно; add-ratings
  заменит на `PopularityScore`.
- [Тайлы OSM при росте трафика] → смена провайдера в `mapStyle.ts`.
