# track-upload Specification

## Purpose
Загрузка и разбор пробежек GPX/TCX/FIT, показатели, скрытые зоны у дома, публикация, фото и статистика профиля (сценарий А, ФТ-2–9).

## Requirements

### Requirement: Supported Files
Система SHALL принимать файлы GPX, TCX и FIT размером до `upload.max_file_bytes` (20 МБ) и обрабатывать их асинхронно в воркере (ФТ-5).

#### Scenario: Valid GPX
- **WHEN** бегун загружает корректный GPX-файл
- **THEN** трек получает статус processing, а затем draft с рассчитанными показателями
- **AND** дистанция отличается от рассчитанной по точкам файла не более чем на 1%

#### Scenario: Same run in three formats
- **WHEN** одна и та же пробежка загружена как GPX, TCX и FIT
- **THEN** дистанция, общее время и набор высоты у трёх треков совпадают с точностью 1%

#### Scenario: File too large
- **WHEN** бегун загружает файл больше 20 МБ
- **THEN** загрузка отклоняется до обработки с причиной «файл больше 20 МБ»

#### Scenario: Unsupported format
- **WHEN** бегун загружает файл, который не является GPX, TCX или FIT
- **THEN** загрузка отклоняется до обработки с причиной «формат не поддерживается»

#### Scenario: Processing time
- **WHEN** загружен корректный файл размером около 20 МБ
- **THEN** воркер завершает обработку не дольше чем за 10 секунд

### Requirement: Track Metrics
Система SHALL рассчитывать дистанцию, общее время, время движения, средний темп, сплиты по километрам, набор высоты и категорию дистанции (ФТ-6). Пороги очистки GPS и остановок читаются из настроек.

#### Scenario: Category assigned
- **WHEN** обработан трек длиной 5,2 км
- **THEN** ему присвоена категория 5 км по границам из настроек

#### Scenario: Stops excluded from moving time
- **WHEN** в треке есть остановка на 2 минуты
- **THEN** общее время включает остановку, а время движения — нет

#### Scenario: Kilometre splits
- **WHEN** обработан трек длиной 10,3 км
- **THEN** у него 10 полных сплитов и последний неполный сплит на 0,3 км

#### Scenario: Working geometries
- **WHEN** трек обработан
- **THEN** для него сохранены геометрия для сопоставления с равным шагом `geometry.resample_step_m` и упрощённая геометрия для карты с допуском `geometry.simplify_tolerance_m`
- **AND** обе построены только по видимой части

#### Scenario: GPS spike ignored
- **WHEN** в треке есть точка-выброс, требующая скорости выше `metrics.max_point_speed_mps`
- **THEN** выброс не учитывается в дистанции

### Requirement: Implausible Tracks Rejected
Система MUST отклонять файлы без отметок времени и треки со средним темпом быстрее 2:30 мин/км, сообщая причину (ФТ-7).

#### Scenario: No timestamps
- **WHEN** в файле нет отметок времени
- **THEN** трек получает статус rejected с причиной «в файле нет времени»

#### Scenario: Too fast
- **WHEN** средний темп трека 2:10 мин/км
- **THEN** трек получает статус rejected с причиной «похоже на транспорт»

### Requirement: Duplicate Detection
Система SHALL распознавать повторную загрузку того же файла тем же пользователем.

#### Scenario: Same file again
- **WHEN** бегун загружает файл, который уже загружал
- **THEN** новый трек не создаётся, бегун получает ссылку на существующий

### Requirement: Home Privacy Zones
Система MUST хранить трек целиком, но отдавать другим пользователям только часть между выходом из скрытой зоны в начале и входом в неё в конце (ФТ-4), и сохранять границы видимой части.

#### Scenario: Start inside zone
- **WHEN** трек начинается в 150 м от дома при радиусе зоны 300 м
- **THEN** публичная геометрия начинается в точке выхода трека из зоны
- **AND** API для других пользователей не содержит ни одной точки внутри зоны

#### Scenario: Owner preview
- **WHEN** автор открывает превью своего трека
- **THEN** он видит весь трек и затенённую скрытую зону

#### Scenario: No home set
- **WHEN** у бегуна не задана точка дома
- **THEN** видимая часть трека совпадает со всем треком

#### Scenario: Zone changed later
- **WHEN** бегун меняет точку дома или радиус
- **THEN** видимая часть всех его треков пересчитывается

#### Scenario: Track entirely inside zone
- **WHEN** весь трек лежит внутри скрытой зоны
- **THEN** его можно опубликовать только как приватный, с объяснением причины

### Requirement: Publication and Visibility
Обработанный трек SHALL оставаться черновиком, видимым только автору, пока тот не опубликует его с видимостью public, link или private (ФТ-8). Чужим пользователям public- и link-треки доступны по ссылке, в списках треков бегуна — только public.

#### Scenario: Publish public track
- **WHEN** бегун публикует трек с названием и видимостью public
- **THEN** трек виден другим по ссылке и в списке треков бегуна

#### Scenario: Private track
- **WHEN** бегун публикует трек с видимостью private
- **THEN** другие пользователи получают 404 по ссылке на трек, и трека нет в списке треков бегуна

#### Scenario: Link-only track
- **WHEN** бегун публикует трек с видимостью link
- **THEN** трек открывается по ссылке, но его нет в списке треков бегуна

### Requirement: Track View and Navigation
У трека SHALL быть экран просмотра для всех, кто может его видеть, и отдельная форма публикации и редактирования для автора. С формы MUST быть явный выход «Назад»; после публикации или сохранения форма закрывается и открывается просмотр трека.

#### Scenario: After publishing
- **WHEN** бегун публикует трек или сохраняет изменения
- **THEN** форма закрывается и открывается просмотр этого трека с подтверждением

#### Scenario: Leave the form
- **WHEN** бегун нажимает «Назад» на форме трека
- **THEN** он возвращается на предыдущий экран, а если его нет — на просмотр трека

#### Scenario: Draft view
- **WHEN** автор открывает просмотр своего черновика
- **THEN** он видит пометку «Черновик» и кнопку «Опубликовать», ведущую в форму

#### Scenario: Pace values shown
- **WHEN** открыт трек со сплитами
- **THEN** на графике темпа по километрам подписаны значения темпа

### Requirement: Track Photos
Бегун SHALL прикреплять к треку до 5 фото JPEG, PNG или WebP; метаданные EXIF, включая координаты, удаляются (ФТ-8).

#### Scenario: Sixth photo
- **WHEN** бегун добавляет шестое фото к треку
- **THEN** загрузка отклоняется с причиной «не больше 5 фото»

#### Scenario: Photo location stripped
- **WHEN** бегун загружает фото с координатами в EXIF
- **THEN** сохранённое фото не содержит EXIF с координатами

### Requirement: Edit and Delete
Бегун SHALL редактировать название, описание и видимость своего трека и удалять его (ФТ-9).

#### Scenario: Edit track
- **WHEN** бегун меняет описание и видимость своего трека
- **THEN** изменения сохраняются, другие видят трек согласно новой видимости

#### Scenario: Delete track
- **WHEN** бегун удаляет свой трек
- **THEN** трек, его фото и исходный файл удаляются из БД и S3

#### Scenario: Foreign track
- **WHEN** бегун пытается изменить или удалить чужой трек
- **THEN** запрос отклоняется с кодом 404

### Requirement: Profile Statistics
Профиль SHALL показывать число пробежек, суммарные километры и личные рекорды по категориям (ФТ-2) и ленту треков (ФТ-3). Публичный профиль считает только public-треки, собственный — все обработанные.

#### Scenario: Guest sees only public tracks
- **WHEN** у бегуна есть public, link и private треки, и гость открывает его профиль
- **THEN** гость видит статистику и ленту только по public-трекам

#### Scenario: Personal record
- **WHEN** у бегуна два трека в категории 5 км со временем 25:10 и 24:30
- **THEN** личный рекорд в категории 5 км — 24:30

### Requirement: Account Deletion Cleanup
Удаление аккаунта MUST удалять все треки пользователя, их фото и исходные файлы.

#### Scenario: Delete account with tracks
- **WHEN** бегун с загруженными треками удаляет аккаунт
- **THEN** его треки исчезают из БД, а их файлы и фото — из S3

### Requirement: Upload Rate Limit
Система MUST ограничивать загрузку `upload.rate_limit_per_hour` (20) файлами в час на пользователя.

#### Scenario: Limit exceeded
- **WHEN** бегун загружает 21-й файл за час
- **THEN** загрузка отклоняется с указанием, когда можно продолжить
