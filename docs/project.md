# Контекст проекта

## Purpose
Веб-приложение для бегунов. Бегун загружает пробежку (GPX/TCX/FIT); система сама находит,
совпадает ли она с маршрутом, который раньше опубликовал кто-то другой, и сравнивает время.
Быстрее автора — ачивка «Превзошёл». Вызовов как отдельной сущности нет: соревнование
возникает автоматически из совпадения маршрутов.

Полное ТЗ: `docs/tz.md`. Этот файл — справка для людей и агента; ограничения для OpenSpec — в `openspec/config.yaml`. Отложенные идеи (не реализовывать): рейтинги без привязки
к маршруту, сегменты, монетизация.

## Tech Stack
- Backend: Python 3.12, FastAPI, SQLAlchemy 2 + Alembic, Pydantic v2
- Geo: PostgreSQL 16 + PostGIS 3, shapely, pyproj (метрические расчёты в локальной UTM-проекции)
- Разбор файлов: gpxpy (GPX), fitparse (FIT), lxml (TCX)
- Очередь: Redis + Celery (разбор файлов и сопоставление — только в воркере)
- Файлы: S3-совместимое хранилище (локально MinIO)
- Frontend: React 18 + TypeScript + Vite, MapLibre GL JS, TanStack Query
- Инфраструктура: Docker Compose для разработки, GitHub Actions CI
- Тесты: pytest (+ testcontainers для PostGIS), Vitest, Playwright для e2e

## Project Conventions

### Code Style
- Python: ruff + black, mypy strict для `app/domain`.
- TypeScript: strict, eslint + prettier.
- Тексты интерфейса — на русском, через i18n-ключи с первого дня.
- Единицы в БД: метры, секунды, секунды на км. Форматирование — только на фронте.

### Architecture Patterns
- `backend/app/api` — HTTP-слой; `app/domain` — чистая логика без I/O
  (расчёт показателей, скрытые зоны, сопоставление, сравнение);
  `app/infra` — БД, S3, очередь.
- Правила сопоставления (раздел 5 ТЗ) — чистые функции в `app/domain/matching`,
  все пороги берутся из таблицы настроек, не из констант.
- Попытка — это Track со ссылкой `parent_track_id` на исходный трек.
- API описан OpenAPI (генерируется FastAPI); фронт генерирует клиент из схемы.

### Testing Strategy
- Каждый Scenario в спеках — минимум один автотест.
- Фикстуры треков лежат в `backend/tests/fixtures/tracks/`: реальные GPX
  (линейный маршрут, круговой, с разминкой, со сходом с маршрута, два круга,
  с шумом GPS у зданий). Сопоставление тестируется только на них и на синтетике.
- PR не мержится с красным CI.

### Git Workflow
- Trunk-based, короткие ветки `change/<change-id>`, Conventional Commits.
- Одна OpenSpec-изменение = одна ветка = один или несколько PR.

## Domain Context
- Трек — загруженная пробежка с GPS-точками и временем.
- Исходный трек — первый по дате публикации публичный трек маршрута.
- Попытка — трек, автоматически сопоставленный с исходным.
- Группа трека — исходный трек и все его попытки.
- Скрытая зона — круг 200–500 м вокруг дома автора; участки трека внутри
  него хранятся, но другим не показываются.
- Категории дистанции: 1 км (<3), 5 км (3–7,5), 10 км (7,5–15), 21 км (15–25), 21+ (≥25).

## Important Constraints
- 152-ФЗ и GDPR: согласие на обработку, удаление аккаунта со всеми треками.
- Реальные координаты в скрытой зоне никогда не уходят на клиент другим пользователям.
- Приватные треки и треки «по ссылке» не сопоставляются и не попадают в группы.
- Производительность: поиск по области карты ≤ 500 мс на 1 млн треков;
  обработка файла до 20 МБ ≤ 10 с.

## External Dependencies
- OAuth: Google, Apple.
- Тайлы карты: внешний провайдер векторных тайлов (выбрать в add-map-search).
